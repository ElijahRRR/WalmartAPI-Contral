# 通用卖家精灵选品（周循环）

本技能是**项目级技能**，随仓库提交，只在本仓库内使用。它只负责"选出合格产品"，产出本周入选池；
落占用、写上架表/删除表不在本技能内，需要时按 `walmart-standard-selection` 的 H–K 段走（预览 → 所有者确认 → 写表）。

与 `walmart-standard-selection` 的分工：
- 本技能**不绑定类目和参数**：类目从哪读、选多少、卖家精灵七个条件，全部由每周表单决定。
- 采集入库、经营模式检查、必要审核**不另写一套**，直接按 `.agents/skills/walmart-standard-selection/SKILL.md` 的 E、F、G 段执行（下文写明只在哪几处替换参数）。规则改了只改那一份。

路径约定：
- **仓库命令**：在仓库根目录执行，解释器 `.venv/bin/python`；`cli.py …` 指 `.venv/bin/python cli.py …`。
- `<DATA_ROOT>` = `registry.paths.data_root()`（默认与仓库平级的 `WalmartAPI_data`，环境变量 `WALMART_DATA_ROOT` 优先）。
- 类目标准 v2 的 CSV 在 `<DATA_ROOT>/reference/category_standard/`，下文写作 `reference/…`。
- `<…>` 替换为实际值。

## 〇、红线

1. 本技能全程**不写飞书、不落占用、不写上架表/删除表**。会写的只有：本周状态目录、采集批次（`api.scraper.submit_batch` + `pump_batch`，既有采集写路径）、`cli.py product_audit -p asins=`（必要审核）。
2. 编排脚本只读：连库用 `registry.db.pg_conn()`，开只读事务。
3. **条件不自行放宽。** 本周表单里的七个卖家精灵条件和类目范围就是本周口径；类目用完仍不够，汇报缺口并询问所有者（所有者在表单里预先写了放宽方案的，按方案逐级走，只进不退）。
4. **结果不确定先对账，不盲目重提。** `BatchExistsError` 带回的 batch_id 接着用，不换名重提。
5. 每完成一个小动作就立即落盘到本周状态（见第二节），中断后最多丢一个动作。

## 一、周判定

- 所有者在台北，**按台北时间（Asia/Taipei, UTC+8）的 ISO 周**判周：周一 00:00 开始，周日 23:59 结束。
- 周标识 `<WEEK>` 形如 `2026-W48`，用 ISO 年（`%G`），跨年周不会算错：

```bash
.venv/bin/python -c "from datetime import datetime; from zoneinfo import ZoneInfo; print(datetime.now(ZoneInfo('Asia/Taipei')).strftime('%G-W%V'))"
```

- 不用机器本地时区，也不用 UTC 判周（UTC 周一 00:00 时台北已是周一 08:00，周日晚上 16 点后台北已经进入下周）。

## 二、本周状态

目录：`<DATA_ROOT>/exports/sellersprite_selection/<WEEK>/`
（与标准选品的 `exports/selection/` 分开，两个技能同周都跑也互不覆盖。）

| 文件 | 内容 |
|---|---|
| `state.json` | 本周答案、进度、台账（结构见下） |
| `categories.csv` | 本周解析后的类目清单（按执行顺序），`state.json` 只记它的路径和完成到第几行 |
| `exports/` | 卖家精灵导出原件，文件名 `<序号>_<类目ID>_<价区间>.xlsx` |
| `seen_asins.csv` | 本周已经进过流水线的 ASIN（`ASIN,首次轮次,来源导出序号`），用于周内去重 |
| `selected.csv` | 本周入选池（见第五节），**唯一的选品结果** |
| `rejected.csv` | 本周未入选的 ASIN 及原因（采集失败 / F 段排除 / 待核 / 审核拒绝） |
| `rounds/<n>/` | 每轮的提交清单、批次回执、F 段三张表、审核块结果、本轮摘要 |

`state.json` 最少包含（下面 `//` 注释只作说明，实际文件是标准 JSON，不写注释）：

```jsonc
{
  "week": "2026-W48",
  "tz": "Asia/Taipei",
  "created_at": "2026-11-24T10:05:00+08:00",

    "target": 3000,

      "rating_min": 4.0, "reviews": [10, null], "variants": [1, 1], "launch": "近1年"
    },
    "relax": []                    // 所有者预先给的放宽阶梯，空 = 不放宽
  },
  "answers_confirmed_at": "2026-11-24T10:08:00+08:00",
  "answers_history": [],           // 周内所有者明确要求改参数时，把旧答案和改动时间追加到这里
  "progress": {
    "round": 2, "step": "F",       // 当前轮次与段落：PLAN / EXPORT / E / F / G / TALLY
```

写 `state.json` 一律先写 `state.json.tmp` 再改名覆盖，避免中断留下半截文件。

## 三、开始：判断新周还是续跑

每次执行第一步都做：

1. 算出 `<WEEK>`，读 `<DATA_ROOT>/exports/sellersprite_selection/<WEEK>/state.json`。
2. 分三种情况：
   - **不存在** → 本周第一次执行：**重置**，进入第四节发表单。上周目录保留不动，不继承上周的答案、进度和入选池；上周 `status != "done"` 的，在本周第一条汇报里一句话说明上周停在哪、入选了多少。
   - **存在且 `status` 为 `running` 或 `paused`** → **不再提问**，直接用 `answers` 和 `progress` 续跑（第五节，从记录的轮次和段落接着做）。开头一句话汇报：本周目标、已入选、剩余、当前轮次与段落。
   - **存在且 `status = "done"`** → 本周目标已达成，汇报结果（`selected.csv` 路径、数量），不再继续选；所有者明确要求"本周再追加 N 个"时，把 `target` 加 N、记入 `answers_history`，改回 `running` 续跑。
3. 只有所有者**明确说"本周重新开始"**时，才把现有目录改名为 `<WEEK>.reset-<台北时间 YYYYMMDDHHMM>` 保留，再按"不存在"处理。周内改参数同理只在所有者明确要求时做，旧答案记入 `answers_history`，已入选的不作废（它们在旧参数下合格），从改动起按新参数导出。
4. 状态目录里如有 `run.lock` 且写入时间在 2 小时内，说明另一次执行还在跑：停下汇报，不并跑。开始时写入 `run.lock`（含开始时间），结束或暂停时删除。

## 四、本周表单（只在本周第一次执行时）

**一次问完，不分几轮追问。** 运行环境有结构化提问工具（一次可提多个问题、带选项）时用它；没有就把下面整张表单原样发给所有者，请他按编号一次回复，没填的项按默认值。

```
本周（<WEEK>，台北时间 <周一日期>–<周日日期>）卖家精灵选品设置，请按编号回复，未填项用 [默认]：

1. 选品类目从哪里读取
   A. 类目标准 v2 勾选清单 reference/卖家精灵勾选清单.csv，结论为「可选」+「有条件」的全部节点 [默认]
   B. 同 A，但只取以下一级类目：______（如 家居、庭院、宠物）
   C. 同 A，但只取「可选」
   D. 我提供的文件：路径 ______（CSV/XLSX，需有「类目ID」或「完整路径(英文)」列）
   E. 我直接列出：______（卖家精灵类目路径或类目ID，逗号分隔）
   执行顺序：[默认 家居 → 庭院 → 办公 → 户外运动 → 宠物 → 其他]，或写你的顺序：______

2. 本周目标选品数量（入选产品数，独立 ASIN）：______（必填）

3. 卖家精灵筛选条件（写区间或下限，"不限"也可以）
   3.1 亚马逊价格（美元）      [默认 0–40]
   3.2 配送方式                [默认 FBA]（可选 FBA / FBM / 不限）
   3.3 月销量                  [默认 ≥20]
   3.4 评分                    [默认 ≥4]
   3.5 评论数                  [默认 ≥10]
   3.6 变体数                  [默认 =1]
   3.7 上架时间                [默认 近1年]（可选 近1月/近3月/近半年/近1年/不限，或起止日期）

4. （可选）用完类目还不够时怎么放宽
   [默认 不放宽：用完即停下汇报，由我决定]
   或写阶梯，例如：先 评论 5–9；再 变体 2–5
```

收到回复后：
1. **校验**：目标数为正整数；价格、月销量、评分、评论数、变体数的区间合法（下限 ≤ 上限、评分 0–5）；D 选项的文件存在且有类目列；E 选项列出的类目能在 `reference/类目标准_v2_全部节点.csv` 中找到（按类目ID或英文路径匹配）。不合法的项**一次性**列出请所有者改，不逐项追问。
2. **解析类目**生成 `categories.csv`（列：`序号,类目ID,完整路径(英文),完整路径(中文),结论,核实条件,卖家精灵产品数`）：
   - A/B/C：从勾选清单筛选结论与一级类目，按勾选清单的「勾选方式」照抄（整枝勾选就是整枝，末级勾选就是末级）。
   - D/E：所有者给的类目**照样执行**，但逐个用类目标准 v2 查一遍（最长路径前缀匹配），结论为「不选」或查不到规则的，列进确认回显里提示所有者，所有者回"照做"才保留。
   - 按执行顺序排序；同一一级类目内按卖家精灵产品数从小到大，方便小类目合并导出。
3. **回显确认**：用一段话复述本周口径（类目数与来源、目标数、七个条件、放宽方案），以及首轮计划（首轮导出量 = 目标 × 倍数，默认倍数 3；参考上周同技能实测漏斗，若有则取较大值）。所有者确认后写入 `answers`、`answers_confirmed_at`，建 `state.json`，`status = "running"`，开始第五节。

## 五、选品循环

每轮依次走 PLAN → EXPORT → E → F → G → TALLY，每段做完更新 `progress.step` 并落盘。

### PLAN：本轮要导多少
- `剩余 = target − 已入选`；`本轮导出需求 = 剩余 × 倍数`（独立 ASIN）。
- 倍数：第一轮用回显时确认的值；之后用本周实测 `累计导出独立 ASIN ÷ 累计入选`，至少 2。
- 从 `categories.csv` 的 `category_cursor` 往下取类目，直到预计结果数（看页面结果数）够本轮需求。

### EXPORT：卖家精灵导出（浏览器）
- 每次查询都按 `answers.sprite` 七个条件设置，类目为当前类目；条件和本周答案不一致的导出不算数。
- 单次结果 ≤2,000 条（台北时间 19:00–08:00 可到 3,000），尽量接近上限：超了按价格区间拆分再查，再超继续拆；结果少的类目可以合并成一次查询（条件一致）。
- 每天（台北时间）最多 50 次导出，用 `progress.exports_today` 计数，到上限就把 `status` 置 `paused`、汇报，等次日再执行。
- 每次导出后立刻：存原件到 `exports/`，追加 `exports[]` 台账，把**本周没见过的**标准 ASIN（`services.sku_asin.is_standard_asin`）追加到 `seen_asins.csv`，推进 `category_cursor`（一个类目全部价区间导完才推进）。
- 只在**本周内**去重；不因"库里已有/选过/在线/交付过"排除（这些在入选池里标注，由下游分配处理）。

### E / F / G：采集、经营模式检查、必要审核
按 `walmart-standard-selection` 的同名段执行，输入是本轮新增 ASIN，产出放进 `rounds/<n>/`，台账写进 `batches[]`、`audits[]`。只有三处按本周答案替换：
- **E 采集**：批次名用 `ss_<WEEK>_r<轮次>`（如 `ss_2026-W48_r2`）。
- **F1 供货硬条件**：价格上限换成本周 3.1 的上限（下限同理）；配送方式换成本周 3.2（选"不限"时不卡 FBA）。库存 ≥5 且有确切数量、运费已知、货期 ≤7 天、24h 内快照、地区不是 mismatch、退货率 ≤30% 照旧。
- **F2 经营模式**：类目标准 v2 + 商品级排除项**原样适用**，不因本周类目来源不同而放宽。待核比例超过 5% 先停下汇报。

### TALLY：计数与是否继续
- **入选**口径：本周去重后的独立标准 ASIN，同时满足 F1、F2 通过，且审核结论为当前版本的 approved。
- 新入选追加到 `selected.csv`，列：`ASIN,品牌,品牌键,标题,亚马逊类目路径,类目标准结论,价格,运费,库存,配送,货期,快照时间,审核结论,审核版本,入选轮次,来源导出序号,当前是否已在某店在线,品牌占用店`。
  后两列只读查询（`catalog.listing_sources` + `sku_asin.pick_asin`；`services.claims.load_active`），只标注、不排除。
- 未入选的追加到 `rejected.csv`，写明在哪一段、什么原因。
- 更新 `progress.selected / remaining / multiplier`，写本轮小结进 `rounds[]`。
- 判断：
  - **已入选 ≥ target** → `status = "done"`，进第六节。
  - 不够、类目还没用完 → 下一轮（回 PLAN）。
  - 不够、类目已用完 → 有放宽阶梯就 `relax_stage + 1`，把类目游标归零，按新阶段条件只补上一阶段没覆盖的区间（例如评论从 ≥10 放宽到 ≥5 时，只查 5–9），继续循环；没有阶梯或阶梯走完 → `status = "paused"`，汇报真实缺口并询问所有者，不自行改条件。

## 六、交付

本周 `done`（或暂停等所有者）时汇报，并附 `selected.csv`：
- 目标 / 已入选 / 剩余；
- 漏斗：导出次数、导出独立 ASIN、采集成功、F 可送审、F 排除（按原因 Top）、待核、审核通过、入选；本周实测倍数；
- 入选池中"已在某店在线"和"品牌已被占用"的数量（提醒下游分配时会被定向或淘汰）；
- 审核费用合计；
- 用完类目仍不够时：缺口、已走到哪一级放宽、建议的下一步条件（只建议，不执行）。

入选池接下来要分配上架的，按 `walmart-standard-selection` 的 H 段用 `pool_csv=selected.csv` 出预览，所有者确认后再走 J 段；本技能不代做。
