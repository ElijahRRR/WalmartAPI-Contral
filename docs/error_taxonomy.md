## 三、解析规范

### 3.1 输入形态

- **来源 1/2(下架原因)**:库里是 `"; "` 拼接串(api/items.py `"; ".join`)。
  引擎收 `atoms: list[str]`;拆串由调用方用引擎提供的 `split_reasons(text)` 完成:
  按 `"; "` 拆,**但整行含 AI 尾句(§3.4)时不拆整行短路**(AI 文案自身可能含分号)。
  拆分安全性已生产实证:最短原子 36 字符是完整句。
- **来源 3(feed 报错)**:`ops.feed_item_errors` 已逐条,输入 `(code, field, description, status)`。

### 3.2 规范化 `normalize_atom(text)`

1. `html.unescape` 循环至不动点(≤3 次,处理 `&amp;amp;` 双重转义);
2. 剥 HTML 标签:`<[^>]{1,80}>` → 空(生产实见 `<p>…</p>` 包裹整句);
3. 链接标记 `||链文本@@@url||` → 保留链文本、丢 url(与 problem_scan 现有探针同形态);
   **残缺标记**(如 `- )` 结尾、`@@@` 后无闭合)按同规则尽量剥,剥不净不报错;
4. 空白折叠为单空格、去两端;
5. 产出两个副本:`casefold` 副本供句式匹配,原大小写副本供政策名抽取。

### 3.3 原子判定次序(表序即优先级,首命中即码;全部 casefold 子串/正则)

| 序 | 码 | 判据(casefold) |
|---|---|---|
| 0 | `CONTENT`(via_ai=True) | 含 `generated by ai`(整原子短路,正文不再进任何规则) |
| 1 | `PT_WRONG` | 含 `appropriate product type selected` |
| 2 | `PROHIBITED_FINAL` | 含 `not eligible for appeal` |
| 3 | `RECALL` | 含 `cpsc recall` 或 `safety warning` |
| 4 | `FLAGGED` | 含 `flagged by our internal team` |
| 5 | `IP` | 含 `intellectual property` 或 `copyright`,或正则 `\bip\b\s+(policy|claim|related)` |
| 6 | `BRAND` | 含 `brand restrictions` 或 `not authorized to list this brand` |
| 7 | `GATED` | 含 `requires pre-approval` / `restricted to certain sellers` / `request approval to sell` / `enhanced vetting program` / `health & compliance page` |
| 8 | `PRICE` | 含 `pricing rule` / `price gouging` / `unintended price` |
| 9 | `CONTENT` | 含 `content issues` / `does not meet our content standards` / `content quality standards` / `image guidelines` / `placeholder images` —— ⚠ 不许用裸 `content standards`:政策文本里有 "do not meet **offensive** content standards"(sex toys 条),裸串会把政策拒误抢成内容问题(语料有反例钉死) |
| 10 | `SPECIAL` | 含 `resold program` / `preorder program` / `pre-owned` / `restored program` |
| 11 | `INFO` | 含 `no price was found` / `shipping information was not added` / `active distribution center` / `missing required logistics` |
| 12 | `SYSTEM` | 含 `internal error occurred` / `glitch` |
| 13 | `STAGE` | 含 `stage status until you go live` |
| 14 | `EXPIRED` | 含 `end date has passed` |
| 15 | `POLICY` | 含 `prohibited product` 且含 `policy`(覆盖 Products/Product 两形、缺首字母 typo) |
| 16 | `OTHER`(显式) | 含 `business decision` / `trust & safety` —— 计入 `unlisted` 清单,不进 unknown 告警 |
| 17 | `OTHER`(未识别) | 兜底 —— **必进 unknown 告警清单,原文全文保留** |

判据纪律:**不锚句首、不依赖 "This"**(缺首字母 `his item…` 的 29 条 typo 免疫);
判据串一律来自生产原文,禁止拟写。

### 3.4 政策名抽取 `extract_policy(atom_raw)`(对每个原子独立跑,填 `policy_name`,与码正交)

1. 正则(对原大小写副本):
   `Prohibited\s+Products?\s+Polic(?:y|ies)\s*:\s*([^.;|@*]{2,80})` —— **冒号必需**,
   冒号后取候选;无冒号 = 无候选(生产反例:`*Prohibited Product Policy* for Toys`
   类别在标记外、`Children's Products Prohibited Products Policy` 结构反置 —— 都不猜);
   `*…*` 星号包裹形态(feed 侧)与 `||…||` 链文本形态经 §3.2 已剥,统一落这个正则;
2. 候选清洗:去两端标点/空白;剥前置停用词 {`Walmart`, `Walmart's`, `Our`, `The`, `This`};
   截断在首个 `.` `;` `,`(**逗号也截**:"Policy: X, please review…" 的续句不吞);
3. 主/子类拆分:候选含逗号已被截,子类形态 `Offensive Content, Halloween Items` 由
   截断前先查:若逗号后文本 ∈ 已知子类词形(Halloween/Inappropriate/Intolerance/
   Violence/Sex Toys 家族)则 `policy_sub` 收下、主名取逗号前;否则按 2 截断;
4. 无候选的兜底:原子命中 `POLICY` 词根但抽不出类别名(通用政策拒 3,363 条的常态)
   → `policy_name=None`,合法,不告警;
5. 抽出候选但**与政策表 join 不上** → 保留候选原文,进"政策表缺口"清单(报告显示,
   不算 unknown)。join 用 `audit.walmart_prohibited_policy.category_en`,由调用方注入
   字典(引擎纯函数不连库);别名表(如 `Auto and Motor Vehicles`→`Auto & Motor
   Vehicles` 之类的词形差)生在引擎内,**别名的目标值必须在注入字典里,运行时校验**。

### 3.5 记录级归类 `classify_reasons(atoms, policy_names) -> Result`

```python
Result = namedtuple("Result",
    "code name policy_name policy_sub via_ai atom_codes unknown unlisted")
# code      : 主码 = 各原子码按 ERROR_CATEGORY_SEVERITY 首命中
# atom_codes: tuple[(原子码, policy_name|None), ...] 逐原子,供病历附注/报告
# unknown   : 落 OTHER(未识别) 的原子原文列表 —— 调用方必须告警,引擎不吞
# unlisted  : OTHER(显式清单) 命中的词条计数
```

### 3.6 feed 侧 `classify_feed_error(code, field, description, status) -> FeedResult`

```
通道判定(次序):
  1 code ∈ registry 既有 WALMART_ERR_CONTENT,或 description 含 AI 尾句
                                      → channel="content_ai"(码 CONTENT, via_ai)
                                        (code 锚必须保留:生产明细的 description 常被
                                        截断,AI 尾句可能不在截断内)
  2 field ∈ WALMART_ERR_FIELD_POLICY 且 status == "failed"
                                      → channel="policy":正文过 §3.3 序 1-15
                                        (通常落 POLICY/IP,policy_name 照抽)
  3 code ∈ registry 既有 WALMART_ERR_ASYNC_REVIEW → channel="async"(审查中,非报错)
  4 其余                              → channel="operational",原样带回 (code, field)
                                        —— 已结构化,不强行进 16 码表
```

⚠ `status=="failed"` 这道闸是硬的:生产契约里 SUCCESS 回执可以同时带
ingestionErrors(带警告的成功),field 锚不许把它们判成政策拒。
本步 `classify_feed_error` 只被对照报告消费,**不接 `classify_receipt`**。
